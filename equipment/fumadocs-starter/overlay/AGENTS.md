# Documentation project instructions

- Preserve canonical Markdown/MDX source and stable URL paths. Do not edit compiled output.
- Read `.agents/skills/docs-architect/SKILL.md` when intentionally designing or reorganizing documentation.
- Adapt page types to readers' tasks; never force the Diátaxis quadrants into top-level folders.
- Use native Fumadocs `meta.json` and optional nested metadata; validate navigation and internal links.
- Use official Fumadocs components and check imports against installed versions.
- For static export, check search, `basePath`, generated pages and assets; do not add server-only features without adjusting hosting.
- Before changing existing docs, propose a small migration plan and run the project's actual typecheck/build.
