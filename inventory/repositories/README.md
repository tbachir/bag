### Reuse strategy

1. **Inventory** owns each repository reference; the 7 existing BAG zones remain the organizing scheme. Do not mirror entire applications.
2. **Maps & Guides** should receive a *new guide* only for generalizable, reviewed procedures (for example, Windows deployment runbooks or traceable specification workflows).
3. **Skill Tree** should receive a skill only after its complete behavior, scope, security and portability have been extracted and tested. **Spellbook** should receive scripts only after their dependencies and side effects are audited.
4. **Equipment** may host reviewed opt-in configuration examples, with redacted placeholders; **Loadouts** should link to already curated BAG items instead of cloning them.
5. Keep README-unavailable sources in evaluating status. Revisit source trees, project licenses, versions and existing BAG duplicates before promotion to ready.

This initial pass inspected default-branch project READMEs; it did **not** audit or execute implementation files, validate licenses, or test extracted configurations. Treat suggestions as candidates rather than validated reusable modules.
