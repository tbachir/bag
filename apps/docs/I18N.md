# BAG localization contract

## Goals

- English is the canonical source; keep original Markdown and all current `/docs/` URLs stable.
- French is an optional secondary language. Translate incrementally; missing or outdated pages should use the canonical English page rather than return 404 or silently show stale French content.
- Preserve static HTML export, GitHub Pages `/bag` prefix, search, Markdown shortcuts, `llms.txt`, OG images, downloadable files, and Fumadocs navigation.
- Agent instructions such as `AGENTS.md` and `SKILL.md`, file paths, code examples, and configuration are not translated. They are shared references.

## What is prepared now

`i18n.config.json` defines the future locales and fallback. Optional translations will mirror canonical source paths under `translations/fr/`, with a `.source-sha256` sidecar to mark the English revision on which the translation was reviewed. `pnpm translations:check` audits missing, stale, and orphaned translations without changing files. Missing translations are informational, not failures.

## Follow-up before enabling French in production

1. Add Fumadocs locale configuration and locale-aware routing while keeping existing `/docs/` links working (do not silently replace them with `/en/docs/`).
2. Teach the Markdown generator and manifests about per-locale pages and locale-preserving relative links. Keep downloads and agent technical files shared.
3. Build locale-specific navigation, language selector, search index, metadata/hreflang, static Markdown and LLM outputs. Make search visibly language-aware.
4. Add tests for partial translations, fallback, stale revisions, `DOCS_BASE_PATH=/bag`, and full static export before enabling `fr`.
5. Activate French routes only after both normal and prefixed builds, all export checks, and Playwright tests pass.

**Do not claim multilingual output is already live.** No runtime routes are added by this foundation PR.
